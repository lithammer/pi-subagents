# Domain docs

This repo has a single domain context. Keep shared terms in the root
`GLOSSARY.md` and architecture decision records in `docs/adr/`.

Before exploring the codebase, read `GLOSSARY.md` and any ADRs that cover the
area you’re working in. If either is absent, continue with the available context.
Use the glossary’s terms when naming domain concepts. Bring terms and decisions
that need recording to `domain-modeling` as they arise.

If a proposal conflicts with an ADR, cite the ADR and explain why the
decision should be reopened.
